# Tollgate - карта проекта

Документ для передачи разработки: что где лежит, как устроено, какие решения уже приняты и почему. Читать вместе с [README](README.md) (для пользователя), [TODO](TODO.md) (план) и [CHANGELOG](CHANGELOG.md) (история версий).

Текущая версия: **0.6.1** (`__version__` в `tollgate.py`). Репозиторий: https://github.com/sergvss/tollgate

---

## 1. Что это

Виджет для Windows 10/11: иконка в трее и всплывающая панель с лимитами подписок **Claude Code** и **Codex** (ChatGPT): заполнение окон 5ч / 1д / 1н, время до сброса, тариф и срок подписки, уведомления при 80% и 95%.

Долгосрочная цель - «шлагбаум» между пользователем и ИИ: учёт расхода → экономия токенов → классификация запросов → блокировка чувствительных запросов (см. TODO.md, эпики E3-E5).

**Принципы (не нарушать):**
- только локальные данные: сам Tollgate в сеть ничего не отправляет; исключение - раз в 5 минут фоновый `claude -p /usage`, запрос делает Claude Code;
- токены входа Claude и Codex не используются для запросов к API (из `~/.codex/auth.json` декодируется только открытая часть `id_token`);
- чужие настройки не перетираются (статус-строка ставится, только если её нет; перед правкой бэкап).

## 4. Источники данных

Все читаются в `tollgate.py`, функции `read_*`. Каждая возвращает `(окна, время_данных)`, где окно - `(каноническое_имя, процент, unix_время_сброса)`. Канонические имена окон: `5h`, `1d`, `1w` (перевод - `win_name()`).

| Что | Откуда | Поля |
|---|---|---|
| Лимиты Claude (свежие) | `~/.tollgate/claude-usage.json` | `rate_limits.five_hour / seven_day` → `used_percentage`, `resets_at` (unix) |
| Лимиты Claude (запасной) | `~/.claude.json` → `cachedUsageUtilization` | `utilization.five_hour / seven_day` → `utilization`, `resets_at` (ISO); `fetchedAtMs`. Claude Code обновляет кэш редко (раз в часы) |
| | `read_claude()` берёт из двух источников тот, что свежее | |
| Обновление кэша Claude | `refresh_claude_usage()`: `claude -p /usage --no-session-persistence --strict-mcp-config --setting-sources project --no-chrome` из `~/.tollgate`, без окна, ~4 с | Claude Code запрашивает `GET /api/oauth/usage` и пишет `cachedUsageUtilization` (не чаще раза в минуту). К модели не обращается. `--bare` не подходит - в нём нет входа по подписке |
| Лимиты Codex | самый новый `~/.codex/sessions/**/*.jsonl`, последнее событие с `rate_limits` (читается хвост файла 512 КБ) | `payload.rate_limits.primary / secondary` → `used_percent`, `window_minutes` (300 = 5ч, 1440 = 1д, 10080 = 1н), `resets_at` |
| Тариф Claude | `~/.claude.json` → `oauthAccount.organizationType` | `claude_pro` → `Pro` |
| Срок подписки Claude | `oauthAccount.subscriptionCreatedAt` | Даты окончания локально нет - **оценка**: ближайшее месячное продление |
| Тариф и срок Codex | `~/.codex/auth.json` → `tokens.id_token` (JWT, только payload) → claim `https://api.openai.com/auth` | `chatgpt_plan_type`, `chatgpt_subscription_active_until` - **точная** дата |

Codex обновляет `rate_limits` только когда им пользуются, поэтому его данные бывают старыми - возраст показывается в панели.

## 5. Устройство `tollgate.py`

Файл разбит на секции (комментарии `# --- ... ---`):

1. **Константы и темы.** `THEMES` (light/dark: `BG, FG, DIM, TRACK, ALERT_BG, BADGES, PILL, BORDER`), `apply_theme()` переписывает глобальные цвета. `SCALES = (1.0, 1.25)`. Все функции отрисовки читают цвета из глобалов в момент вызова (поэтому у них `bg=None`, а не `bg=BG` - значение по умолчанию вычислилось бы один раз при загрузке модуля).
2. **Локализация.** `LANGS`, `STRINGS` (ru/en/zh), `T(key, **kw)`, `win_name()`, `F(size, bold, lang)` - шрифт с учётом масштаба; для китайского - `Microsoft YaHei UI` (в Segoe UI нет иероглифов).
3. **Чтение данных.** `read_claude*`, `read_codex*`, `read_*_plan`.
4. **Форматирование.** `fmt_left` (до сброса: `2д 3ч`), `fmt_age` (возраст: `12с / 3м / 2ч / 1д`), `effective` (сбросившееся окно → 0%; окно - `(имя, %, до сброса, прогноз)`), `load` / `load_plan` - безопасные обёртки (ошибка не роняет виджет).
5. **История и прогноз.** `History` (глобал `HISTORY`) пишет замеры в `HISTORY_FILE`; `load(reader, name)` с именем провайдера вызывает `HISTORY.track()`, который возвращает `{окно: когда будет 100%}`. `pace_end()` - темп по замерам текущего окна (тот же сброс, допуск 2 мин) за последний час, отрезок не короче 10 мин, данные не старше 30 мин; прогноз только если 100% наступит раньше сброса. В строке панели прогноз заменяет время сброса и красится жёлтым (`r["eta"]`), колонка времени рассчитана и на него - сетка не гуляет.
6. **Картинки (Pillow).** Всё гладкое рисуется в 4x и уменьшается (`LANCZOS`) - иначе tkinter на Windows рисует скругления «лесенкой»: `rounded_bar`, `pin_image`, `glyph_image`, `tray_image`. Значки - из шрифтов `SegoeIcons.ttf` (Win11) / `segmdl2.ttf` (Win10); `PIN_FONTS` хранит угол иглы пина в каждом шрифте, чтобы наклон был одинаковым.
7. **`animate()`** - анимация по реальному времени (ease-out), длительность не растягивается при запаздывающих кадрах.
8. **Класс `Widget`.**

### Жизненный цикл `Widget`

- `__init__`: окно без рамки (`overrideredirect`), поверх всех; загрузка `state.json`; иконка трея (`pystray`) в отдельном потоке - команды из трея идут в tk через `queue` (`_poll` раз в 100 мс; tkinter не потокобезопасен).
- `refresh()` раз в 30 с: читает данные → считает `_layout_key()` → если структура изменилась, `_show_screen()` (готовый экран из `self.screens` или `_build()`), иначе `_update()` на месте → трей → `_place()` → `_check_alerts()` (последним: может открыть панель и вложенно вызвать `refresh`).
- `_tick()` раз в секунду: только тексты возраста данных, без чтения файлов.
- `_usage_loop()` в фоновом потоке: при старте и раз в `CLAUDE_USAGE_EVERY` (5 мин) - `refresh_claude_usage()`, затем `refresh` через очередь. Кнопка обновления и пункт меню трея (`refresh_now`) будят поток сразу (`usage_now`).

### Ключевая идея: реактивное обновление

- **Строится один раз** (`_build`): шапка (`_titlebar`), секции провайдеров (`_section`), строки полосок. Ссылки на изменяемые элементы - в `self.refs`, строки - в `self.rows`.
- **Обновляется на месте** (`_update`): меняются только тексты/цвета/картинки, изменившийся процент анимируется (`_animate`, `_paint_row`).
- **Пересборка** только если поменялся `_layout_key`: вид (лимиты/настройки), язык, тема, масштаб, набор окон, название тарифа и т.п.
- **Готовые экраны.** `self.screens` хранит по экрану на вид (`limits`, `settings`) с ключом раскладки: при переключении экран с тем же ключом не пересобирается, а просто показывается (`place`), другой прячется (`place_forget`); устаревший уничтожается (`_drop`). Ключ настроек включает ширину панели лимитов.
- Подмена - **одним кадром**: `_freeze(True)` (WM_SETREDRAW) → новая рамка → старая спрятана/удалена → `_place()` (размер окна) → `_freeze(False)` + `RedrawWindow` → `update_idletasks()`. Без заморозки виден промежуточный кадр, без `_place` под заморозкой - новое содержимое в старом размере, без `update_idletasks` - смесь двух экранов.

### Сетка панели

Карточка - `grid` из 4 колонок: подпись окна | полоска | процент | время до сброса. `_grid_columns()` задаёт колонкам фиксированную минимальную ширину по самому длинному возможному тексту на текущем языке - при обновлениях сетка не «гуляет». `_fit_bars()` удлиняет полоски, если заголовки шире строк, - правые края совпадают. Общий отступ слева/справа - `self.ip`.

### Окно

- Позиция: правый нижний угол рабочей области (`SPI_GETWORKAREA`) с отступом `MARGIN = 25`; `_place()` двигает окно только при изменении размера.
- Скругление и цвет рамки Windows 11: `DwmSetWindowAttribute` (33 - углы, 34 - цвет рамки). На Win10 игнорируется.
- DPI: `SetProcessDpiAwareness(2)`; все размеры в пикселях - через `px()` (глобал `DPI` × масштаб из настроек), шрифты `F()` - тоже в пикселях (отрицательный размер). `DPI` - масштаб главного монитора (`monitor_dpi()`, на нём панель), `_check_dpi()` перечитывает его в начале каждого `refresh()`; `DPI` входит в `_layout_key`, поэтому смена монитора пересобирает панель.
- Карточка размещается через `place`, поэтому окно не растягивается само: размер берётся из `card.winfo_reqwidth/height`.
- Ширина у лимитов и настроек общая, высота у каждого экрана своя (с 0.6.1; до этого лимиты добирали высоту до настроек и внизу было пустое место). Настройки берут ширину панели лимитов (`limits_size`), панель лимитов - не уже настроек: `_settings_width()` собирает настройки невидимо и измеряет, внизу лимитов невидимая распорка 1px на все 4 колонки держит ширину. Ширину карточки лимитов в момент сборки мерить нельзя: тексты дат и возраста в заголовках появляются только в `_update`.
- Незакреплённая панель прячется по `FocusOut`/Esc; закреплённая (пин) видна всегда и показывается при старте.

### Уведомления

`_check_alerts`: при переходе порога из `THRESHOLDS` (по умолчанию 80/95%, выбор - `ALERT_PRESETS` в настройках, `set_alerts`; `()` - тихий режим, глушит и уведомление о подписке) - `icon.notify()` и автопоказ панели на 10 с (без захвата фокуса). Уровень, о котором уже уведомили, хранится в `self.alerted`; после сброса окна уровень падает и уведомление сработает снова.

Подписка: когда `load_plan` красит срок жёлтым (за 3 дня до окончания), приходит уведомление «подписка заканчивается» - один раз на срок (флаг `self.alerted[(провайдер, "plan")]`, сбрасывается после продления). Панель при этом не открывается. Флаги живут в памяти: после перезапуска виджета уведомление придёт ещё раз.

## 6. Решения и грабли (чтобы не наступить повторно)

| Проблема | Причина | Решение |
|---|---|---|
| Панель мерцала каждые 30 с | Каждый элемент tkinter на Windows - отдельное нативное окно; пересоздание всех элементов видно | Реактивное обновление на месте + пересборка только по `_layout_key` |
| Прыжки окна при переключении | Сначала менялся размер, потом позиция; плюс промежуточные кадры | Размер и позиция одной командой `geometry("WxH+X+Y")`; подмена карточки под `WM_SETREDRAW` |
| Нельзя плавно «перетечь» между разделами | Прозрачность в Windows есть только у окна целиком, не у части содержимого | Пробовали: гашение всего окна (не понравилось - окно исчезает), окно-«призрак» со снимком (отказались - второе окно), въезд сбоку (рвётся отрисовка). **Итог: мгновенная подмена одним кадром.** Плавные переходы возможны только если рисовать всю панель одной картинкой (Canvas/PIL) с обработкой кликов по координатам |
| Снимок экрана 288 мс | `ImageGrab` при нескольких мониторах (у автора 5760×2400) снимает весь рабочий стол | Если снова понадобится снимок - BitBlt нужного прямоугольника (~18 мс); в версии 0.3.2 есть рабочая реализация `grab_region` (см. git) |
| Анимации растягивались | Длительность считалась числом кадров, а кадры запаздывают | `animate()` по реальному времени |
| В тёмной теме кнопки/картинки со светлым фоном | Значения по умолчанию `bg=BG` вычисляются один раз | `bg=None` → `bg or BG` при вызове |
| Иероглифы «цветные» на скриншотах | Сглаживание ClearType | Не баг, на экране серые |
| Иконка трея одинаковая до ~29% | Минимальная высота заливки была большой | Минимум - тонкая точка (`max(6, ...)` из 56 px) |
| Панель мелкая на 4K после отключения внешнего монитора (до 0.3.5) | DPI считался один раз при старте (`winfo_fpixels`), шрифты в пунктах tk тоже переводит по DPI на момент запуска | `monitor_dpi()` при каждом обновлении, шрифты в пикселях, `DPI` в `_layout_key`. Для проверки в тесте подменять `tollgate.monitor_dpi` |
| Тесты перезаписывали настройки пользователя | Тестовый `Widget` сохранял `state.json` | В тестах подменять `tollgate.STATE_FILE` на временный файл **до** создания `Widget` |
| При переключении лимиты ↔ настройки была видна дорисовка (до 0.6.1) | Экран каждый раз собирался заново (~60 мс, ~50 нативных окон) | Готовые экраны (`self.screens`), подмена ~20 мс; прелоадер отвергнут - при таком времени он бы только мелькал |
| Лимиты Claude не обновлялись при работе в десктоп-приложении (до 0.6.0) | Десктоп-приложение (`entrypoint: sdk-ts`) не вызывает статус-строку, а кэш `~/.claude.json` Claude Code обновляет редко - после смены тарифа панель часами показывала старые 85% | Фоновый `claude -p /usage` раз в 5 минут - Claude Code сам обновляет кэш. Свой запрос к API с токеном отвергнут: нарушает принцип «без токенов» |
| Пилюля порогов срабатывала только один раз | `_segmented` блокирует клики, пока пилюля едет, а разблокировки не было: язык/тема/масштаб всё равно пересобирают панель, пороги - нет | Флаг `busy` снимается, когда пилюля доехала |
| Незакреплённая тестовая панель «не меняла размер» | Она пряталась при потере фокуса, а скрытая панель размер не пересчитывает | В тестах ставить `w.pinned = True` (только в памяти) |

**Известные несоответствия:** анимация полосок (`Widget._animate`) считается по кадрам (`ANIM_FRAMES`, `ANIM_MS`), а остальные анимации - по времени (`animate()`); при желании перевести полоски на `animate()`.

## 7. Как запускать и проверять

```
pythonw tollgate.py                 # обычный запуск (трей + панель)
python -X utf8 tollgate.py --print  # данные в консоль, без окна - быстрая проверка чтения
```

Перед перезапуском убить старый экземпляр (повторный запуск сразу выходит из-за мьютекса `tollgate-single-instance`):

```
powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter \"Name='pythonw.exe'\" | Where-Object { $_.CommandLine -like '*tollgate.py*' } | ForEach-Object { Stop-Process -Id $_.ProcessId }"
```

**Визуальная проверка** (так проверялись все изменения): скрипт импортирует `tollgate`, подменяет `STATE_FILE` и `HISTORY_FILE`, при необходимости подменяет `Widget.PROVIDERS` фиктивными данными (например, 92% для подсветки), создаёт `Widget`, вызывает `show()`, выполняет действия по таймеру (`root.after`) и снимает скриншоты окна. Что проверялось:

4. Коммит на русском с глаголом в начале («Добавить …», «Исправить …»), тег `vX.Y.Z`, `git push origin main` и `git push origin vX.Y.Z`.
