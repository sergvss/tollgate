# Tollgate - план разработки

Цель проекта: шлагбаум между пользователем и ИИ. Видно, сколько потрачено. Расход можно сократить. Чувствительное не уходит в модель.

Принципы, которые не нарушаем:
- **Локально.** Данные пользователя и тексты запросов никуда не отправляются.
- **Без токенов.** Токены входа Claude и Codex не используются для запросов к API.
- **Не ломать чужое.** Чужие настройки (статус-строка, хуки) не перетираются, перед правкой делается бэкап.

Статусы: `[x]` сделано, `[ ]` в планах. В скобках - целевая версия.

## E1. Мониторинг расхода (0.1 → 0.2)

Цель: в любой момент видно, сколько осталось и когда сбросится.

- [x] Лимиты Claude Code: 5ч и неделя (0.1)
- [x] Лимиты Codex: окна из подписки ChatGPT (0.1)
- [x] Свежие данные Claude после каждого ответа через статус-строку (0.1)
- [x] Тариф и срок подписки: Codex точно, Claude оценкой (0.1)
- [x] Прогноз: «при текущем темпе 5ч-окно кончится через ~40 мин» (0.4) - точность на реальных сессиях ещё не измерена
- [ ] История расхода за 7 дней: мини-график в панели (замеры уже копятся в `~/.tollgate/history.jsonl` с 0.4)
- [ ] Отдельные недельные лимиты по моделям (Opus и т.п.), если Claude Code их отдаёт (0.2)

Готово, когда: прогноз отличается от факта не больше чем на 20% на реальных сессиях.

## E3. Экономия токенов (0.3)

Цель: понять, что сжигает лимит, и тратить меньше.

- [ ] Разбор локальных логов Claude Code (`~/.claude/projects/**/*.jsonl`) и Codex: расход по проектам и сессиям
- [ ] Доля кэша (cache read и cache write), чтобы видеть сессии с плохим кэшированием
- [ ] Топ «дорогих» действий: большие файлы в контексте, длинные выводы инструментов
- [ ] Подсказки по ходу работы (хук `UserPromptSubmit`): «контекст 80% - сделай /compact», «файл на 5000 строк - укажи диапазон»

Готово, когда: на своих логах видно топ-5 источников расхода и хотя бы одна подсказка срабатывает автоматически.

## E4. Классификация запросов (0.4)

Цель: понимать, на что уходят запросы, без хранения их текста.

- [ ] Локальный классификатор на правилах: код, отладка, вопрос, текст, данные, чувствительное
- [ ] Хранить только метку и размер, без текста запроса
- [ ] Сводка в панели: распределение по категориям за день и за неделю

Готово, когда: на 100 своих запросах точность меток не ниже 85% (ручная разметка).

## E5. Шлагбаум: блокировка чувствительных запросов (0.5)

Цель: секреты и персональные данные не уходят в модель случайно.

- [ ] Хук `UserPromptSubmit` для Claude Code: проверка промпта перед отправкой
- [ ] Детекторы: API-ключи и токены (sk-, ghp_, AKIA, JWT), приватные ключи, пароли в строках подключения, номера карт (Luhn), паспорта и телефоны
- [ ] Хук `PreToolUse`: запрет чтения `.env`, `*.pem`, `~/.ssh` и т.п.
- [ ] Режимы: предупредить или заблокировать, плюс allowlist для ложных срабатываний
- [ ] Журнал блокировок (без самого секрета, только тип и место) и счётчик в панели
- [ ] Codex: выяснить, есть ли аналог хуков, и подключить

Готово, когда: набор тестовых промптов с секретами блокируется на 100%, а обычные промпты без секретов пропускаются в 99% случаев.
